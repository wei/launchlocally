How LaunchLocally works

LaunchLocally takes a product URL and a target market, and returns a launch video in the local language plus an interactive brief where every claim opens its source. The full reference is the README in the repository.

How a run works

  1. Input. You paste a product URL and pick a market. Japan (ja-JP) is the default. The reverse pack (en-US) launches a Japanese product globally in English.
  2. Research. 12 agents run in parallel with Tavily. 5 read the official site (brand, product, pricing, customers, docs) and 7 search the target market using the areas and queries in the market pack. A language model turns the pages into facts. Each fact keeps its source URL.
  3. Script. A language model writes a four-scene script (hook, product, proof, call to action) in the local language, plus a design brief. A sentence stays only if it cites a fact_id that exists in facts.json.
  4. Voice. A Kokoro voice model on a Nosana GPU deployment narrates each scene.
  5. Compose. Local code builds a baseline Hyperframes HTML composition from the script, the brand profile and the audio.
  6. Code. CodeAF writes theme.css, a stylesheet that makes the video look like the official site, adapted to the market's style rules. It runs beside research, script and voice. The theme is used only if it passes the checks and the Hyperframes lint.
  7. Render. A Daytona sandbox renders the composition to MP4 with headless Chrome and FFmpeg, and serves the result.
  8. Buyer gate. A local buyer persona from the market pack scores the script of each cut. Three verdicts: approve; reject, when an unused sourced fact would fix the concern, in which case the script is revised and cut 2 is voiced and rendered; and approve_with_gaps, when the video already uses the evidence that exists and the rest is for the vendor to provide.
  9. Output. The launch video and an interactive brief. Clicking a claim opens its source.

AgentField runs steps 2 to 8. Each stage is its own node in the workflow graph.

The run directory

Stages communicate only through files in runs/<run_id>/. Each stage can be run alone from the command line against a run directory.

Add a market pack

A market is one JSON file in packs/. The repository has packs/ja-JP.json and packs/en-US.json. To add a market, copy one to packs/<id>.json and edit:

  • language, language_name, country, currency
  • voice: the Kokoro voice and language code
  • search: country and local sites
  • research_areas: the market research agents and their query templates
  • copy_rules, style_rules, cta_examples: how the script and the video should read and look
  • buyer_persona: who reviews the cut, what they care about, and the questions they score

The server lists every file in packs/ (GET /api/packs), so the new market appears in the picker without code changes.

Run it

You need Python 3.12 with uv. Put TAVILY_API_KEY, DAYTONA_API_KEY, NOSANA_API_KEY and OLLAMA_API_KEY in .env at the project root.

export PATH="$HOME/.agentfield/bin:$HOME/.codeaf/bin:$PATH"

# 1. AgentField control plane, port 8080
af server --open=false

# 2. LaunchLocally agent node, port 8001
.venv/bin/python -m launchlocal.agents

# 3. Web app, port 8787
.venv/bin/python -m launchlocal.server

Open http://127.0.0.1:8787, paste a URL and pick a market. The workflow graph is at http://localhost:8080/ui/ under Workflows.

Run single stages against a run directory:

.venv/bin/python -m launchlocal.voice <run_id> [market]
.venv/bin/python -m launchlocal.compose <run_id>
.venv/bin/python -m launchlocal.coder <run_id> [market] --theme
.venv/bin/python -m launchlocal.render <run_id>

Fallbacks

Each external dependency has a named fallback that writes a log event to events.jsonl when it is used.

  • Language model chain. Nosana hosted inference first, then the project's own Nosana GPU deployment when one is configured, then Ollama Cloud. Each run logs which provider served it.
  • Local voice. If the Nosana voice endpoint fails, the same Kokoro model runs on the local CPU.
  • Local render. Used only when LAUNCHLOCAL_RENDER=local is set. It is never chosen silently.
  • Baseline look. If the CodeAF theme fails its checks, the video renders with the baseline stylesheet.
  • Cached-run replay. A recorded run opened with ?replay=1 replays its recorded events and shows a "CACHED RUN" badge.
